# Lessons learned

Project-specific rules accumulated across sessions. Every agent reads this at the start of any non-trivial task and applies the relevant rules as a checklist.

## Editing rules — APPEND-AND-SUPERSEDE ONLY

- **Never reword or delete a lesson body.** Past lessons are historical record.
- **Supersede** via a new entry whose last line is `Supersedes: L-NNN`. Both entries stay; the newer one wins by precedence.
- **Maintained by the `retrospective` agent.** Direct edits should be rare; non-trivial changes land as proposals in `docs/evolution/` first.
- Format: each lesson is a one-liner (≤3 sentences) with an `L-NNN` id and a source citation. Supporting detail belongs in a skill file the lesson links to, not inline here.

## Framework operation (seeded with the install; supersede as the project teaches better)

- L-001 — Read `project-profile.md` → `lessons.md` → `patterns.md` → matching skill BEFORE doing real work. Skipping orientation is how the same mistake recurs. *Source: framework design.*
- L-002 — Reflect AFTER every meaningful task: append one line to `interactions.jsonl` (`scripts/capture.sh`). Unreflected work teaches the framework nothing. *Source: framework design.*
- L-003 — Expand the framework on **evidence, not momentum**: a pattern recurred ≥3× or one mistake was costly. Building tooling because it feels productive is the failure mode this rule prevents. *Source: framework design.*
- L-004 — Every self-edit is one atomic git commit (`evolve: <what> — <why>`). This is the revert safety net; a self-modifying system without it is unsafe. *Source: framework design.*
- L-005 — No agent edits inside any `## INVARIANTS` fence — not even `retrospective` on itself. To change an invariant, file a task for the user. *Source: framework design.*
- L-006 — When memory conflicts with the user's request, surface the conflict before acting. Stale memory followed silently is worse than no memory. *Source: framework design.*

## Project lessons (extracted from real work)

- L-007 — **Profile continuously, every interaction — never wait for session end.** Project understanding is built as a small inline delta after each meaningful turn (new tech/convention/goal/vocab/correction → update `project-profile.md` then), NOT batched. The heavy `scout` agent is for the initial deep scan and major changes only; don't spawn it per turn. A project must never sit `UNPROFILED` after the first real interaction. *Source: the project sat UNPROFILED across 8 evolutions because profiling was designed as a deferred "first activity" event (2026-06-22 evolution analysis).*

- L-008 — **Verify the artifact before closing the session.** When a new capability is built (agent, script, CLI, MCP tool), run or test it in the same session — never mark it done unverified. Unverified work is technical debt that compounds silently. *Source: 4 of 5 major builds in IX-005 through IX-009 explicitly verified in-session; the ones that didn't shipped blind (2026-06-22 retrospective).*

- L-009 — **Park heavy bets; ship the lean version; never silently drop scope.** When a feature proves too heavy (platform, Docker, Go stack), move it to a branch (`platform-alpha`) rather than dropping it, and record the reason in `backlog.md` with a `dropped`/`deferred` status. Lean version ships on `main`. *Source: pattern recurred 3× — Docker/Postgres dropped for local MCP (IX-005), Go platform parked on platform-alpha (IX-004), heavyweight autopilots deferred (IX-003) — all handled identically (2026-06-22 retrospective).*

- L-010 — **A spec/design change to a gated artifact always flows `review-360` (0–100, critical-floor aggregation) → `change-approver` (APPROVE/REJECT: overall >80, all CRITICAL dims ≥70, zero blockers) before it is committed.** Re-review rounds are named by suffix, first round unsuffixed (`<slug>-review.md`), subsequent rounds `-review-r2.md`, `-r3.md`… and the decision record mirrors it (`<slug>-decision.md`, `-decision-r2.md`). The approver authorizes; it never applies the commit. *Source: the flow ran 9+ times in one sprint (A1, A5, B1–B4, §16, §17/§18, §19), averaging ~3 rounds and ~82/100, and caught two real, high-consequence defects (§17 round-1=45: item-generation immutability hole enabling data poisoning; §19 round-1→r2: gate governed only the statistical clause, not generalization/cumulative clauses) — not a rubber stamp (2026-07-02 retrospective). See `skills/spec-change-gate/SKILL.md` for the full playbook.*

- L-011 — **Never assume the unattended daemon ran — verify its last run log before relying on it.** `.claude/daemon/launchd.err.log` and `.claude/daemon/runs/*.log` are ground truth; a "daemon enabled" state is not evidence it executed successfully. *Source: the daemon has never completed a successful unattended run — 2026-06-22 install left `scripts/evolve.sh` without the executable bit (`Operation not permitted`, every launchd tick), and after that was worked around, two runs (2026-06-25, 2026-06-26) failed with `401 Invalid authentication credentials`; all in-session evolution to date has been manual/inline, never daemon-driven (2026-07-02 retrospective, first self-audit pass).*

- L-012 — **`turing-agents` is read-only from this repo — always.** This repo (MDLP) manages only the research/spec side; `/Users/samyoga/dev/turing-agents` is the user's own separate implementation. Audit or report on it freely (`Explore`/read tools), but never write, edit, or commit there — any information it needs to receive crosses back only via the user, manually. *Source: recurred correctly 3× as read-only audits (IX-014 2026-06-25, IX-030 2026-07-02, IX-036 2026-07-03) plus 2 dependent result-recording interactions (IX-032, IX-033); already stated in `project-profile.md` and the user's global memory but not yet in the lessons checklist every agent reads first per L-001 — high-consequence if ever violated, so it belongs in both places (2026-07-03 retrospective).*

- L-013 — **Before resubmitting any gated spec/schema change, do a schema-first edit + an end-to-end contradiction read + a grep-verify of every cross-reference — don't resubmit on narrative confidence alone.** The single defect class the review-360 gate caught most often across the 2026-07-13 external-study build cycle (5+ distinct instances across all three multi-round artifacts — S17.6 lineage schema, DATA-LAYER §6.1/6.2, B2 Amendment A — some documents' own reviews naming it "the Nth recurrence of the class of defect X caught") was: (a) claiming a schema field, registration, or cross-reference exists/was fixed without actually writing it (a delta line, a §12 parameter, a Port-delta signature), or (b) fixing the defect at one location while a co-dependent location (a `Record schemas` section, an adjacent bullet describing the same mechanism, a Protocol code block) is left stale and now contradicts the fix. The fix that worked, repeated verbatim in the successful late rounds: edit the schema/registration location FIRST, then re-read the full artifact end-to-end looking specifically for two passages describing the same mechanism differently, then `grep` every symbol/field/parameter name touched across all files that cite it before resubmitting. *Source: IX-039 (2026-07-13), corroborated across evolution-log.jsonl EV-48/51/53/54/56/57/59/60/61/65/66/67 (S17-6 rounds 2/4/5/6, DL-write-discipline rounds 2/3/6/7/9/10/11, B2-amendA round 4) — ~30 review rounds total, all four artifacts eventually reached APPROVED once this checklist was actually followed. See `skills/spec-change-gate/SKILL.md` "Pre-submission authoring checklist" for the caller-side playbook.*

- L-014 — **Before re-running a stalled or degraded multi-agent/background research workflow, inspect its journal/log file for salvageable state — don't re-run from scratch on the assumption the output was lost.** A synthesis/summary stage can misfire (e.g. return placeholder text) or a run can be cut short by a session/token limit while the underlying per-step journal already holds the full results; recovering from the journal costs one pass of parsing versus the full cost of the original run. *Source: IX-042 (2026-07-28) — 110-agent research run's synthesis stage returned a placeholder ("Test summary.") while `journal.jsonl` held all 131 claims + 74 verify votes intact; recovered directly from the journal rather than re-running. Corroborated by IX-038 (2026-07-13) — a 102-agent research run hit a session token limit mid-run and `resume-from-runId` (the same underlying pattern: trust the persisted run state over re-starting) recovered it cleanly with a cached prefix. Two occurrences on the same class of tool, both high-consequence (100+ agent runs are expensive to redo) — not yet 3x, revisit if a third instance narrows the rule further.*

- L-015 — **Grade a source's class before harvesting from it, and match claim strength to source strength.** A primary transcript yields structural/method content a derivative walkthrough won't (the Ousterhout lecture transcript vs. the blog); a position paper supports scope claims but never mechanism claims (Zahavy — its own review thread softened "confirms" to "suggests," and public rebuttals exist); a short non-research artifact (a 2-page beginner guide) donates isolated devices, not a study — write nothing about it as a studied source. *Source: 3 instances 2026-08-12/13 — IX-048/049 (transcript vs. walkthrough), IX-054 (guide → 2 devices, no study doc), IX-055 (position-paper grading); STUDY-ontologies-and-raft.md §4, STUDY-llms-cant-jump.md, PLAN-harvest-2026-08.md §4.*

- L-016 — **A mechanism-level mapping between two systems is not a problem-level identity.** Before leaning on a structural comparison ("the parts correspond"), check whether the underlying *problems* match — an unusually clean-feeling mapping is exactly the case to check hardest, not skip. *Source: the Raft↔MDLP property-list isomorphism, IX-051 (2026-08-13, owner-caught, retracted in place) — one high-consequence instance (it briefly steered the property-list proposal toward "derivable from Raft's," which was wrong); NOTE-ungated-harvest.md §1, SYNTHESIS-raft-ontologies-peer-learning.md ML-1.*

- L-017 — **When studying an external system for adoption, deliberately look for where it is WRONG for the target problem, not only where it fits — misfit analysis is more generative than fit analysis.** Raft's argmax-completeness voting rule being wrong for peer teaching produced the ZPD band; the Vulcan absorption pattern being a misfit for Zahavy's own framing produced the `coherent_with`-absorption liveness finding — the two most novel results of the 2026-08-12/13 arc, both from misfit. *Source: IX-051, IX-055 (2026-08-13); SYNTHESIS-raft-ontologies-peer-learning.md ML-3.*

- L-018 — **When defining a new relation or schema type, elicit its constraints proactively — solicit weak spots and convert each to a stated constraint, or derive them from a classification pass — rather than waiting for a review round to trip over a missing one.** 3rd instance of the same pattern: L-013's authoring-defect class, B2 Amendment A's acyclicity check arriving as a late-round caught gap, and the unnamed constraint inventory in `STUDY-ontologies-for-mdlp.md` §2. Mechanical fix: RAF-7c (weak-spot→rule, landed in `skills/spec-change-gate/SKILL.md` this run) and ONT-3 (OntoClean-derived constraints, gated spec work) — related to but distinct from L-013 (that lesson is verify-before-resubmit; this one is elicit-before-first-use). *Source: STUDY-ontologies-for-mdlp.md §2 (2026-08-12), PLAN-harvest-2026-08.md §4.*

- L-019 — **Authoring-side self-checks (a pre-submission checklist, then RAF-7's three legibility devices) cannot eliminate the asserted-not-demonstrated guard/citation defect — only the independent `review-360` pass reliably catches it, every time, before anything ships.** In the 2026-08-13 autonomous wave the defect recurred 5+ times with RAF-7 devices actively applied pre-submission (§21 r1: guard-vs-universal gap despite grep-verified guards; §21 r2: invented lineage field; DATA-LAYER §12 r2: stale ArtifactStore-blob bullet; §20.10 r5: half-applied citation fix; §10.1 r1: an invented §19.1 `w_obs` mechanism, r2/r3: a fabricated `(§18.7, existing)` test citation + a desynced duplicate guard list) — yet zero instances shipped; `review-360` caught every one at round 1. Stop adding pre-submission author-checklist items for this specific class (the skills lane is paused after 2 ineffective attempts — EV-77, EV-102); budget one review round for it as an expected cost of a gated change, the way the skill file already treats a 45-78 round-1 score as normal. *Source: interactions.jsonl IX-060/061/062/063 (2026-08-13); evolution-log.jsonl EV-102 self-audit (`ineffective`); docs/research/reviews/S10-1-epoch-discipline-review.md:30. Related to but does not supersede L-013 (the defect shape) or L-018 (proactive elicitation) — this lesson is about the empirical ceiling of authoring-side self-checking for it.*

- L-020 — **A simplification that touches a safety margin (a threshold, a retention window, a trip/rollback condition) must carry a quantified before/after sensitivity in its impact statement, not just a preserved/strengthened/modified-with-argument tag.** Two 2026-08-13 wave instances traded safety margin for tidiness and the gate caught both: `κ_reval`'s proposed retirement was quantified by the reviewer as a **2× increase** in the evidence margin required to trip rollback-to-freeze on an unvalidated-in-generation fallback (reversed; kept byte-identical, reframed as a rule-obligation with a never-loosen clamp); PR-8(iii)'s heartbeat predicate would have required a schema mechanism change smuggled in as a checker predicate (honestly downgraded instead of built). *Source: docs/research/reviews/S10-1-epoch-discipline-review.md:29 (κ_reval, round 1); docs/research/reviews/DL-conformance-checker-review.md (PR-8(iii), round 1); interactions.jsonl IX-061, IX-063.*

- L-021 — **When a reviewer challenges a claim's derivability or checkability, narrow the claim to what the artifact demonstrably holds — never re-argue the same claim in stronger words.** This is the default response, not one option among several: the honest-narrowing move succeeded roughly 8 times across the 2026-08-13 wave (predicates downgraded to what schemas hold, claims narrowed to what control flow settles), while its inverse — re-arguing a claim `review-360` had already rejected — produced the wave's only round regression (§20.10 round 3, calibration scored 55, down from round 2's higher mark). *Source: interactions.jsonl IX-062; docs/research/reviews/S20-10-learning-liveness-review-r3.md (regression), S20-10-learning-liveness-review-r4.md (the narrowing exit that recovered it).*

- L-022 — **An agent with a Write-only toolset (no Edit, no Bash) must never attempt to "append" to a shared append-only file via full-file Write — it must return the line for the orchestrating session (which holds Bash/Edit) to append instead.** A single such attempt truncated `.claude/memory/evolution-log.jsonl` from 133 records to 1 (EV-121, 2026-08-13); two other same-day `change-approver` instances independently declined to Write the file and supplied their line for orchestrator-append instead (EV-120, EV-122) — 3 data points on one structural hazard class, not an isolated instance-level mistake. Fixed framework-side this run by rewriting `change-approver.md` and `review-360.md`'s evolution-log-record instructions to require exactly this. *Source: evolution-log.jsonl EV-121, EV-120, EV-122; interactions.jsonl IX-062.*

- L-023 — **Wiring a built-but-unwired construct onto a live path is itself a test — budget for it to surface latent defects that isolated construct-level tests and spec review cannot.** The H4 patch series wired five previously-inert constructs and found a genuine defect at *each* wiring site, not before: tied-observation isotonic pooling silently returned the first tied outcome (H4-2); a global-LIFO rollback retired the wrong skill cross-skill (H4-3); the pooled-band calibration mean-remap pulled an unlearnable skill's competence *up* (H4-2 finding); a store-layer merge left a skill as its own prerequisite via a self-loop on absorption (H4-9); per-item observation floors cleared in a single tick, judging binomial noise as signal (H4-3/§14.3 finding). Extends P-001: "built-but-unwired" is not just a design gap in the abstract — placing the *apply* stage on the live path is where the defect actually surfaces, empirically, every time it was tried this arc. *Source: patches/h4-series/README.md (findings 1, 3, 5; patches 0001/0002/0007); interactions.jsonl IX-066, IX-069 — 5 distinct defects across one 9-patch build.*

- L-024 — **In Auto Mode, keep Bash invocations single-purpose and use the Edit tool for file content, not Bash.** Compound commands that mix a test run with `git add`/`commit`, or a long heredoc-built commit message, repeatedly tripped the classifier during the H4 patch series and had to be split into separate single-purpose commands (one command per test run, one per stage/commit, concise commit messages, Edit tool for any file content) to get a clean run. *Source: interactions.jsonl IX-066 ("the auto-mode classifier blocks compound bash (test+commit mixed) — single-purpose commands pass; Edit tool for code, Bash for git/pytest is the stable pattern"), recurring across the 9-commit H4 patch series (2026-08-18/19).*
