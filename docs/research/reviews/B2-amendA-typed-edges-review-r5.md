## Findings by dimension

### 1. Correctness

- **The `τ_traverse` closed-loop defect (r4's headline Correctness finding) is genuinely fixed.** `BUILD-SPECS.md:222` now specifies that below-floor edges are traversed at rate `q_edge` (default 0.1) rather than never — this is a real, working re-admission channel: a below-floor `P→S` edge can still be walked (10% of the time), can still reach candidacy if `significant(θ−ĉ_mastery[P], SE[P])` holds, can still be confirmed, and its post-redirect outcome check (base Mechanism 3, `:189`) can still fire and renew `confidence` via `g.decay_edges()`. `test_tau_traverse_soft_floor_with_inverse` (`:239`) targets the exact single-dependent-prereq regression r4 identified as unbuildable. This closes the derivation gap r4 found (a test asserting a re-admission path the mechanism gave no way to exercise).
- **`gap_z` is now a real, checkable formula, correctly distinguished from `priority`.** `:228`, `gap_z(P) = (θ − ĉ_mastery[P]) / SE[P]` — this is exactly `priority(e→P)`'s second term (`:225-226`) *before* the frontier z-scoring is applied, which is the right design choice given `gap_z` must be comparable across triggers/backlog entries rather than within one walk's frontier population. No sign error, no scale mismatch with the aging-bump unit ("+1 z-unit per skipped trigger," also `:228`).
- **The aging-survives-eviction argument is logically sound.** A monotonically, unboundedly accumulating bump added to a bounded competing distribution eventually dominates — the same proof structure already accepted (in earlier rounds) for the confirmation-budget queue's aging mechanism, now correctly extended to the occupancy queue. No new derivation error found.
- **Unresolved: the arrival-damping claim at `:228` remains inaccurate about which mechanism does the work it credits.** "Arrival is damped by the `τ_traverse` soft floor... the round-3 unbounded-arrival objection's structural fix" is checked directly against round 3's own stated objection (`B2-amendA-typed-edges-review-r3.md:52`, reaffirmed in its adversarial pass, `:112`): "nothing bounds how many **new** significant candidates can arise per trigger — the amendment explicitly removes the type short-circuit... and no fan-in cap is stated." That objection concerns the volume of **freshly-significant** candidates from the no-type-short-circuit collection design (`:222`, "Edge type never drops a candidate") — edges that have **never been decayed** and are therefore, by definition, above `τ_traverse` and walked "normally" (i.e., at full rate, every trigger, per `:222`'s own wording). `τ_traverse`/`q_edge` only throttle **re**-arrival of **already-discredited** edges — a narrower, RC-4-adjacent concern, not round 3's original one. The actual mechanism that bounds backlog size regardless of arrival composition is `Q_max`'s hard occupancy cap plus lowest-`gap_z` eviction (same sentence, same line) — which genuinely does the job round 3 asked for. So the *guarantee* round 3 wanted (bounded backlog / bounded wait, not just no-permanent-exclusion) does appear to be delivered in round 5 — but by `Q_max`+eviction+aging, not by `τ_traverse`, and the text credits the wrong parameter. This is a factual misstatement about mechanism attribution inside the spec's own prose, not a math error in a formula — it does not by itself break the delivered guarantee, but it is exactly the kind of misattribution that would mislead an implementer tuning `q_edge` into believing they are controlling fresh-candidate backlog pressure, when they are not.

But `§19.1`'s `q_explore` is explicitly an **isolated shadow/canary mechanism** — `ALGORITHM-v0.2-pathway-learner.md:562`: "isolated by invariant: shadow runs never touch real competence, users, or the live posterior; outcomes are recorded only." `q_edge`, by contrast, is **not** isolated: a quota-walked below-floor edge that reaches candidacy is confirmed with real held-out items and, if confirmed, triggers a real Tutor redirect (base B2 Mechanism 4, `BUILD-SPECS.md:190`) — a live decision, not an observation-only probe. Citing `q_explore` alongside these blurs a load-bearing distinction (isolated-observation vs. live-decision quota) that the codebase itself treats as safety-relevant. Non-blocking (the mechanism's substance is sound and has a genuine live-precedent, `§5.3`/R1's `ε_ret`), but a real precision gap in a spec whose own provenance note (`:215`) makes a point of citing patterns accurately.

## Strongest adversarial objection

The amendment now has **two** anti-starvation mechanisms doing conceptually the same job at two different layers — the confirmation-budget queue's aging bump (rounds 3–4) and, as of this round, the occupancy queue's aging-survives-eviction bump (`:228`) — and both rely on the same unbounded-accumulation argument: a skipped/evicted candidate's advantage grows without cap until it eventually dominates any *fixed or bounded-in-distribution* competing population. Neither mechanism states a **cap on the age bump itself**. This means a candidate that is old enough (skipped or evicted enough times) can, by construction, eventually outrank a **freshly-arriving candidate with an arbitrarily larger true `gap_z`** — the aging bump has no ceiling, so there is no stated bound on how large a true-severity gap it can override once it has accumulated enough triggers. This is the aging mechanism's own reflection of the identical problem it was built to solve: round 4's adversarial objection was that the occupancy queue had *no* protection against a real, moderate-severity candidate being evicted forever; round 5's fix removes that failure mode by making the protection *unbounded* in the other direction — an old, only-moderately-severe candidate can eventually and permanently out-prioritize a brand-new, much more severe one, for as many triggers as it takes the fresh candidate to itself accumulate a comparable bump. Given that base B2's founding purpose is to find the **root** (most severe, most causally central) gap and prioritize it, and this amendment's own priority/`gap_z` machinery exists specifically to rank by "how real/severe the gap is," an unbounded age term that can override an arbitrarily large severity difference is a real, if second-order, tension with the amendment's own stated goals — it trades "starvation is impossible" for "arbitrarily large priority inversions are possible," and states neither the cap that would bound the trade-off nor a reasoned argument for why an uncapped bump is the right default. This is not raised in any of the nine dimensions above (Completeness/Implementability note the missing formula and test for the eviction comparator; this is the compound, mechanism-level consequence of that formula, once written, having no ceiling).
